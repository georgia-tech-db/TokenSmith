## Version 14 Implementation

- Preparation locates passage openings in immutable source text rather than asking a
  model to rewrite content or count line IDs. Anchors tolerate whitespace differences,
  but not changed words, ambiguous matches, reordering, or invented mathematics.
- The unfinished last passage is reconsidered with the next window when it fits.
  Large passages retain linked parts. Retry feedback includes the rejected output.
- SQLite persists parent identity and part ordering. Retrieval expands a matched part
  to its indexed parent up to 12,000 characters, scoped by collection and document.
  Larger or incomplete parents remain individual matching parts and are flagged as
  incomplete. Existing indexes without parent metadata continue to work unchanged.
- The two-chunks-per-section cap is removed. Source rank, keyword coverage, and the
  existing exercise handling still apply; model-aware prompt budgeting remains final.
- Source-unit boundaries are explicit in the answer prompt. The rewrite instruction
  distinguishes an identified topic from an identified work/example/claim.

`sourceUnitComplete` means the indexed parent was reconstructed, not that an LLM
correctly discovered a whole poem/theorem or that the entire unit fitted the prompt.
The prompt budget separately reports truncation. Old collections need an explicit
Update to acquire parent metadata; no library is silently reprocessed.

## Reproduce

Create a local JSON mapping of `poems`, `sec`, `calculus`, `looking_glass`, and `slides`
to the PDFs. The case definitions in `tests/benchmarks/document_units_cases.json`
specify physical pages, boundary assertions, and seed questions. PDF contents and
generated answers remain in the chosen local output directory, not in the repository.

```sh
app_runtime/python/bin/python tests/experiments/evaluate_document_units.py \
  --documents /absolute/path/to/document-files.json --out tmp/document-unit-evaluation
node tests/experiments/evaluate_document_answers.mjs \
  --input tmp/document-unit-evaluation/results.json \
  --out tmp/document-unit-evaluation/answers.json --organic
```

The preparation runner exits nonzero if any case fails. The answer runner records
those preparation failures; it does not turn missing cases into passes. Answer text,
suggestions, rewritten queries, sources, budgets, and timings are saved for inspection.
There is **no automatic answer-quality grade** in this experiment.

CI unit tests exercise exact coverage, anchor validation, bounded linked parts, cache
reuse, retry feedback, schema migration, collection/document isolation, source expansion,
and budgeted prompt formatting. Their model calls are stubbed; semantic model quality
must be checked separately. The five real PDFs are not bundled as CI fixtures.

## Remaining work

Preparation needs a reliable structural signal for dense PDF layouts, not more claims
that a valid JSON response proves correct boundaries. Evaluate layout-aware extraction
and boundary classification against this same gate before changing the default again.
Separately, contextual rewriting must retain the enclosing referent, and generator
evaluation must catch circular explanations and unsupported generalizations.

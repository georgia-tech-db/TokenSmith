-----------------------

and question-building script before preparation. Do not rebuild or revise these

For a fresh run
---------------
Preserve this result directory. Make a new sibling directory under
tests/experiments/ and copy the four frozen input files listed in freeze.json,
freeze.json itself, protocol.txt, run.py, answers.mjs, and make_review.py into it.
Use the new directory in the commands above and a new empty --work directory.
Do not copy answers.json or the blind key: the answer runner resumes saved work.
Do not run build_cases.py, which would reconstruct rather than preserve the freeze.
Both arms must use the same corpus path because file names can affect retrieval.
The original source snapshot was downloaded as a GitHub tarball of the pinned SHA.

Create a new blind packet, score all answers against their frozen criteria without
reading blind-key.json, and only then decode labels. manual-scores.json shows the
review schema: reviewId, score (0/1/2), supported, and a short reason. Score 2 means
both criteria met without a material false claim. Score 1 is partial; score 0 is
a wrong core answer or refusal. Support is judged against the supplied original
sources, allowing equivalent passages beyond the predeclared target IDs.

The saved build_report.py recomputes statistics for THIS run; several explanatory
paragraphs contain its observed counts/timings and should not be blindly reused
as a general report generator for a different run. Its paired bootstrap uses seed
157 and 20,000 draws, clustering retrieval paraphrases by concept.
